Waffle Iron — Architecture

A browser-based, MIT-licensed parametric CAD system. The geometry kernel runs in WebAssembly inside a Web Worker; the UI is Svelte 5 + three.js/Threlte. Generated read-only from the repo at 2026-06-19. Hover diagram nodes for tooltips; click the File Reference Table for source locations.

Kernel layer (Rust→WASM) Engine layer (Rust→WASM, in Worker) Bridge layer (Rust/WASM + JS glue) Presentation layer (Svelte/three.js, main thread) Dev-only oracle (non-WASM)

Layering rule. Cargo dependencies enforce an acyclic DAG: cad-primitives ← {cherchi-rs, ssi-rs} ← yang-rs ← kernel-v2 behind the Kernel/KernelIntrospect traits in waffle-types. The legacy crates/kernel/ was deleted at the Phase 6 migration (2026-06-11).

Zero-copy mesh transfer. get_body_vertices uses js_sys::Float32Array::view(&mesh.vertices) — a direct view into WASM linear memory, invalidated by memory growth, so the worker copies into fresh buffers and passes them as postMessage transferables (true zero-copy to the main thread).   STRICT --> FB

Resolution order is Role first (cheapest, exact), then Signature (similarity-based over TopoSignature: surface type, area, centroid, normal, length — see modeling-ops/src/diff.rs:160), then Query (filter+tiebreak over the created set). Position selectors are viewport-only and error in the engine. The provenance loop closes the cycle: every op's role assignments feed the next op's GeomRef resolution, enabling stable references across rebuilds even when topological IDs change.
