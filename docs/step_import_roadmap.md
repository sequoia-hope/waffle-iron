# STEP Import Roadmap — Plan of Record

> Task #138. User goal (2026-07-11): import a STEP file (canonical case: a
> KiCad-exported PCB, e.g. `minihexa.step` — AP214 written by OpenCascade),
> position it with an XYZ offset + rotation, and make it a **first-class
> body**: sketch on its faces, build offset planes from them, reference its
> geometry in sketches, and participate in booleans. A multi-body STEP is
> wrapped into ONE composite body (per-body handling deferred by user).

This document is the single source of truth for the STEP-import effort, in
the same role `docs/yang_functional_roadmap.md` plays for the boolean stack.

## 0. Ground truth about the input (measured, 2026-07-11)

Real KiCad-ecosystem fixtures (downloaded to `refs/step/`, gitignored — the
kicad-packages3D license is CC-BY-SA-4.0-with-exception, so we do not commit
them; committed test fixtures are generated by us, see §5):

| fixture | solids | faces | surface census |
|---|---|---|---|
| `R_0603.step` (chip resistor) | 1 | 26 | 18 plane, 8 cylinder — **entirely in kernel-v2 vocabulary** |
| `SOT-23.step` (transistor) | 1 | 69 | 36 plane, 12 cyl, **16 b-spline** |
| `USB_C.step` (connector) | **34** | 515 | 459 plane, 48 cyl, 4 torus, 4 cone |

Conclusions that shape the design:
1. **B-spline surfaces are unavoidable** (any molded package). kernel-v2's
   exact `Surface` enum (plane/cylinder/cone/torus, sphere in flight #136)
   cannot represent a general import, and OCC-written files are only closed
   to OCC tolerance — they would not pass `validate_solid` exactness
   invariants anyway. **Therefore an imported body is NOT an arena solid.**
2. **Multi-solid single files are the norm** (34 solids in one connector) —
   the composite wrap is needed even below board level.
3. A full board export is an OCC **assembly** (product tree +
   `NEXT_ASSEMBLY_USAGE_OCCURRENCE` + `ITEM_DEFINED_TRANSFORMATION`), one
   product per footprint model plus the board body.
4. KiCad declares `SI_UNIT(.MILLI.,.METRE.)` — file units are mm; the engine
   world is meters. Unit scan is mandatory (§3.4).

## 1. Dependency decision: truck-stepio + truck-meshalgo, git-pinned

**Adopted:** `truck-stepio` (`in` module) + `truck-meshalgo` (tessellation)
+ `truck-assembly`, pinned at git rev `baf8cd5fb7b1c495169d902745f8b42427df66f9`
(ricosjp/truck master, 2026-07-06). Apache-2.0, pure Rust, actively
maintained.

Verified by experiment (scratch harness, this session):
- All three fixtures parse, assembly-walk (`Table::from_step` →
  `table.step_assy()` → DAG with per-edge transform matrices), and
  tessellate (`shell.robust_triangulation(tol)`) with zero failures;
  USB_C (0.8 MB, 34 solids) takes **68 ms** end-to-end in a dev build.
- The meshed shell is `CompressedShell<Point3, PolylineCurve,
  Option<PolygonMesh>>` — **per-face meshes and per-edge polylines**, which
  map 1:1 onto our `RenderMesh.face_ranges` + `EdgeRenderData` contract.
- Pre-mesh faces carry truck's analytic `Surface`
  (ElementarySurface Plane/Sphere/Cylindrical/Toroidal/Conical | SweptCurve |
  BSplineSurface | NurbsSurface) — analytic metadata survives for signature
  and sketch-plane purposes.
- The whole subset compiles for `wasm32-unknown-unknown` on stable.

Why not the alternatives: published truck-stepio 0.3.0 lacks
`manifold_solid_brep` + the assembly walk (master-only); `ruststep` alone
means hand-writing all geometry/topology conversion; foxtrot is an
unmaintained-as-library demo (good reference reading only). The published-
crates.io upgrade path is to re-pin when ricosjp releases; vendoring the nine
truck crates is the fallback if git-dep availability ever becomes a problem.

**Containment rule:** truck types must not leak past `crates/step-import/`.
The kernel stack, feature-engine, and the app see only the neutral
`ImportedBodyData` contract in `waffle-types` (A15/clean-room hygiene: truck
is a *file-format* dependency, not a kernel dependency).

## 2. Representation: mesh-backed imported body (kernel-v2 adapter level)

A new body kind stored in `KernelV2Adapter` beside `solids` — behind the
same `KernelSolidHandle` namespace, so the trait boundary is unchanged:

- **Per face:** triangle mesh (positions/normals/indices) + `ImportedSurface`
  descriptor (Plane{origin,normal} / Cylinder / Cone / Sphere / Torus /
  Freeform) + boundary-edge indices.
- **Per edge:** polyline + endpoint vertex indices.
- `tessellate()` → concatenated `RenderMesh` with per-face `face_ranges`;
  `extract_edges()` → polylines; `list_faces/face_edges/edge_faces/...` →
  from the stored adjacency; `compute_signature` → surface_type string
  ("planar"/"cylindrical"/…/"freeform"), area/centroid/bbox/normal from
  metadata + mesh.
- Imported entity `KernelId`s are minted in a reserved high namespace so
  they can never collide with arena ids.

**Why this gives the user features for free** (verified against current
code): sketch-on-face resolves the picked face via `compute_signature`
(`feature-engine/src/rebuild.rs:1741` requires `surface_type == "planar"`)
plus the mesh triangle in JS (`store.svelte.js` `computeFacePlane`); offset
datum planes (`planes.js` `offset-face`) use the same two paths. Face picking
is `face_ranges`-driven. None of it knows how the body was built.

**Booleans** on imported bodies are a typed wall in SI1
(`KernelError::NotSupported`, surfaced as a toast), then real in SI2 via the
mesh pipeline — an imported body is already exactly what Yang Stage 2
(cherchi-rs exact mesh boolean) consumes. Analytic-only imports (R_0603
class) can later enter the exact arena (SI5).

## 3. Architecture (SI1)

```
JS file picker ──ImportStep{name, step_text}──▶ wasm-bridge dispatch
  → deflate+base64 blob → Operation::ImportedBody{params} → engine.add_feature
feature-engine rebuild:
  blob ──(cache by content hash)──▶ step-import::parse_step ──▶ ImportedBodyData
  transform(scale·unit, rotation Euler XYZ deg, translation) applied to a clone
  ──▶ modeling-ops::execute_import ──▶ Kernel::import_body + tessellate/edges
  ──▶ OpResult{Main: BodyOutput}
```

### 3.1 New crate `crates/step-import/`
Pure Rust, wasm-clean. Deps: truck-stepio/meshalgo/assembly (git-pinned) +
`waffle-types`. Public API:
- `parse_step(text: &str, tol_mm: f64) -> Result<ImportedBodyData, StepImportError>`
  — parse → assembly walk (bake each path's matrix) → per-shell per-face
  tessellation → neutral data, **in meters** (unit scan §3.4). All solids
  and free shells from all assembly paths concatenate into ONE
  `ImportedBodyData` (the composite wrap).
- `transform_imported(data: &mut ImportedBodyData, rot_deg: [f64;3], offset_m: [f64;3])`
  — rigid transform of mesh + analytic descriptors (exact on descriptors).
- Deterministic: sequential iteration, no rayon entry points.

### 3.2 `waffle-types` contract additions (`src/kernel/`)
- `ImportedBodyData { source_name, shells: Vec<ImportedShellData> }`,
  `ImportedShellData { faces: Vec<ImportedFaceData>, edges: Vec<ImportedEdgeData> }`,
  `ImportedFaceData { surface: ImportedSurface, positions, normals, indices, edge_indices }`,
  `ImportedEdgeData { polyline }`, `ImportedSurface` enum (runtime-only, no
  serde — the persisted artifact is the STEP blob).
- `Kernel::import_body(&mut self, data: &ImportedBodyData) -> Result<KernelSolidHandle, KernelError>`
  with a trait-default `NotSupported` (same pattern as `export_step`);
  `MockKernel` override for engine unit tests.

### 3.3 Feature + persistence
`Operation::ImportedBody { params: ImportedBodyParams }` in feature-engine
(`types.rs`), with
`ImportedBodyParams { name, step_blob: StepBlob {encoding:"deflate-base64", data},
translation_m: [f64;3], rotation_deg: [f64;3], scale: Option<f64> }`.
The blob serializes inside the FeatureTree JSON (`WaffleFileV3` unchanged,
`FORMAT_VERSION` stays 3 — new Operation variants are additive under
`#[serde(tag="type")]`). Rebuild re-executes the import; an engine-level
template cache keyed by blob hash makes transform edits cheap (no re-parse).
`EditFeature` re-sends the operation — the UI dialog must round-trip the
existing blob untouched (it edits only transform fields).

### 3.4 Units
truck ignores STEP unit entities (they live in complex instances). A small
scanner in step-import reads the exchange for
`LENGTH_UNIT()/SI_UNIT(.<prefix>.,.METRE.)` (and
`CONVERSION_BASED_UNIT('INCH',…)`) and derives file-unit→meter scale;
default mm with a diagnostic warning if absent. User `scale` multiplies it.

### 3.5 Bridge + UI (SI1)
- `UiToEngine::ImportStep { name, data }` → dispatch compresses, builds the
  Operation, `add_feature` (lands in tree + undo). Transform edits go through
  the existing `EditFeature`.
- Toolbar `import-step` tool + hidden `<input type=file accept=".step,.stp">`
  (clone of `loadProject()` pattern); `ImportStepDialog.svelte` with numeric
  XYZ offset (mm) + rotation (deg) rows (GearDialog is the layout model);
  `featureIcon()` case; add `'ImportedBody'` to the boolean-dialog candidate
  filter (`store.svelte.js:4058`) — it will hit the typed wall as a toast
  until SI2, which is the honest state.

## 4. Milestones

- **SI1 — imported composite body, positionable, sketchable (THIS increment).**
  Crate + contract + kernel-v2 mesh-backed body + feature + persistence +
  UI + fixtures/tests. Sketch-on-face, offset planes, face/edge picking work
  on planar imported faces. Booleans = typed `NotSupported` wall.
  DONE WHEN: import R_0603/USB_C-class files, position via dialog, sketch on
  a planar face, save/load round-trips, `./scripts/test.sh fast` green.
- **SI2 — booleans with imported bodies (mesh path).** Imported mesh ×
  tessellated native solid through cherchi-rs (Yang Stage 2 + ray-cast
  in/out); result is a mesh-backed body with provenance-classified faces.
  Unlocks "pocket the enclosure with the board".
- **SI3 — sketch references to imported geometry.** Project imported edges
  (polylines; exact arcs where the STEP edge was a circle) into the active
  sketch as construction geometry; datum axis from an imported cylinder axis.
- **SI4 — assembly fidelity + scale.** Per-component sub-bodies behind one
  feature (user deferred), board-scale performance (LOD/tolerance policy),
  inch units, richer diagnostics for unsupported entities.
- **SI5 — exact ingestion for analytic-only imports.** R_0603-class bodies
  (plane/cylinder/cone/torus + line/arc edges only) enter the kernel-v2
  arena as exact solids → full yang booleans, analytic primacy end-to-end.

Generated by us with truck-stepio's `out` module (writer) so they are

## 6. Risks / decisions ledger

- **Git dependency availability** — pinned rev; Cargo.lock committed;
  vendoring is the fallback. Re-pin deliberately, never track master.
- **WASM binary size** — truck subset adds weight; measure at SI1 WASM
  rebuild, budget check in the PR description.
- **Determinism** — meshalgo CDT (spade) is deterministic for identical
  input; we iterate sequentially. If drift is ever observed, pin by sorting
  input order (tests will catch: fixture-hash assertions).
- **Board-scale files (10–50 MB)** — linear extrapolation from USB_C says
  seconds, acceptable for SI1; LOD policy deferred to SI4.
- **Sphere signature** — `TopoSignature.surface_type` string for spheres
  exists ("spherical"); kernel-v2 arena sphere (#136) is unrelated to this
  path.
- **2026-07-11** — decided mesh-backed representation over arena ingestion
  (b-splines + OCC tolerance make exact ingestion impossible in general);
  decided truck git-pin over 0.3.0+custom-assembly-walker (walker exists
  upstream, tested).
